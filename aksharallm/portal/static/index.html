  –
  Stopping is safe at any step: the trainer saves
  ckpt_last.pt where it stopped and the next start resumes there with no loss
  spike.
  The explainer runs on your machine through Ollama and
  writes nothing. It shares the GPU with training — configs/portal.yaml keeps
  its context small and unloads the model a few minutes after you stop asking.
  Every job shells out to
  python -m aksharallm.quant — the same command you would type — and writes its
  measurements to logs/quant/. int8 is free; int4 costs perplexity and
  saves memory, not time. See docs/10 for why smaller is not faster.
  An adapter is a few MB, not a new copy of the model — one
  base plus one adapter per skill. Jobs shell out to
  python -m aksharallm.train.sft and write beside the base they came from, so
  the Playground picks them up. See docs/11 for why the rank and the target layers matter
  more than anything else here.
  Every generation is recorded in
  logs/playground.jsonl with the step and loss of the checkpoint that produced
  it, so the same prompt at step 7,000 and step 30,000 can be put side by side. While a run
  is training this loads on the CPU instead of the GPU.
