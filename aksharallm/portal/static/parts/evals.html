Contamination

If a question and its answer already appear in the training data, the model may be remembering rather than reasoning — and the score is a rumour. This looks for any run of 13 tokens shared between each benchmark item and the whole training corpus.

The question leaking is normal — benchmark questions are public text. The question with its answer attached is the one that matters, and the two are counted separately.

Anything less than the whole corpus gives a lower bound — the result says so, and says how much it read.

Per-domain loss

The blended run reports one validation number over 85% prose and 15% Python. That average is mostly prose, so the model's Python ability is nearly invisible in it — and either half can move without the total saying so.

The split is checked, not assumed: each region's content has to match the source it claims to be, and the parts must blend back to the run's own val loss.

Is its confidence honest?

Everything above asks whether the model is right. This asks whether, when it says it is 80% sure, it is right 80% of the time — which is the more useful question for anything that has to be trusted rather than benchmarked.

A model can be accurate and badly calibrated, or inaccurate and well calibrated. Accuracy cannot tell those apart. Temperature scaling cannot change accuracy at all, so it is free.

How much of the corpus is the same thing twice?

A duplicated document is trained on twice — a silent, unrequested extra epoch on whatever happened to be popular. Exact matching cannot see near-duplicates and all-pairs cannot be computed, so: MinHash signatures, LSH banding, union-find.

Read the token share, not the document share: dropping 200,000 forty-token stubs changes nothing. And take two offsets — a sample from the front of a file is a sample of how the file was ordered.
