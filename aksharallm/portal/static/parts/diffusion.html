One token at a time, each one final the moment it is chosen. Sixty-four tokens cost sixty-four forward passes, and the past can be cached.

Masked diffusion

▁ ▁ ▁ ▁ ▁ ▁ ▁ ▁ cat ▁ ▁ . The ▁ cat sat ▁ . The big cat sat on .

Every position predicted on every pass; the most confident ones are committed and the rest stay blank. You choose how many passes to spend — and there is no cache, because any position may still change.

No diffusion checkpoint yet. Train one with scripts/experiment.sh tiny-diffusion — or pick tiny-diffusion on the Dashboard and press Start. It is the same trainer, the same budget and the same data as the tiny baseline; only the objective differs. See docs/19.

1 · What it is trained on

no model runs here — this is the forward process, applied to your text

Training draws that rate uniformly at random for every sequence, so the model learns to fill one blank in twenty and nineteen in twenty from the same weights. The 1/t weight is what stops the near-blank sequences — which have the most blanks and therefore the most loss terms — from dominating the gradient.

2 · Watch it resolve

the finished sentence says nothing about the order it was decided in; this does

Green is a position committed on this step; the darker it is, the surer the model was. Grey is still blank. Try random order and the same seed of steps — the text gets noticeably worse, because committing the easy positions first is what gives the hard ones something to agree with.

3 · Infilling — the thing an ordinary model cannot do

give it both ends and it writes the middle, conditioning on both

An autoregressive model has no mechanism for this: it conditions only on what came before, so "and fell asleep." cannot influence what it writes. Here it is the same code path as above, with the fixed positions in a different place.

4 · What the numbers mean

and the one comparison that is never valid
This model's validation loss is not comparable with an autoregressive one's. An AR run's val loss is the exact per-token cross-entropy of held-out text, and exp() of it is a real perplexity. This one is a Monte-Carlo estimate of an upper bound (an ELBO). If the tiny baseline reads 1.472 and this reads 1.9, this model is not "0.43 worse" — it is "at most this bad, by an unknown margin". Compare the text, and compare what it can do that the other cannot.

Loss by mask rate is the diagnostic with no autoregressive equivalent: at 5% masked the model is doing a cloze test with almost all of the context, at 85% it is nearly writing from scratch. A model that is good only at the left of that chart will infill well and generate badly, and the single val number will not say so.
