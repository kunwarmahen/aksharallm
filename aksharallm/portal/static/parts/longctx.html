How far can it read?

a model re-reads the whole conversation for every token it writes — the context window is how much of it fits

A language model has no memory. Each time it produces a word it re-reads everything before it, and the context window is simply the largest amount it can re-read at once. Ours was trained on windows of about a page and a half.

Show it more than that and it does not gradually get vaguer — it falls off a cliff. Position is encoded as a rotation angle, and past the trained window the model is being handed angles it has never seen, so every comparison it makes between words becomes noise.

The fix is arithmetic, not training: change how positions map to angles. No weights change — which is why you can try all of it on a finished checkpoint in an afternoon. The full chapter is in doc 18.

Measure it

two different questions, and the second is the honest one

Loss by position

Is it still fluent out there? Runs one long window and reports the loss of every position separately. Flat is healthy; a cliff is a naive extension. Cheap, and it needs no downloads.

Needle in a haystack

Can it still retrieve out there? Hides a made-up fact at a chosen depth in a lot of ordinary text and asks for it back. A model can be perfectly fluent at position 6,000 and completely unable to find anything there — fluency is local, retrieval is not.







  

    
What reading that far costs

    attention compares every word with every earlier word, so doubling the context quadruples the work
  

  

    
To decide what comes next, the model scores every word against every word before it.
      That is a grid — 1,000 words means a million scores; 8,000 words means
      sixty-four million. Written naively, that grid is built in memory, and
      it is the reason long contexts run out of it rather than merely running slowly.

    
FlashAttention never builds the grid. It walks the text in blocks and
      keeps a running total, rescaling as it goes, so the answer is exactly the same
      and the memory stops growing. We wrote our own, in Triton, forward and backward —
      doc 3 has the derivation.
